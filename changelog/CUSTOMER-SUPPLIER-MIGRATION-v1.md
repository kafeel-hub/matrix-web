# Customer/Supplier React migration v1

## Preserve-first audit
The current baseline React Customer/Supplier UI files were byte-identical to the Old React App versions before this migration:
- CustomerForm.jsx
- SupplierForm.jsx
- CustomerMaster.jsx
- SupplierMaster.jsx
- CustomerMasterConstant.js
- SupplierMasterConstant.js

Therefore the existing tested modal/table UI was retained.

## Integration changes
- Added `src/services/partyMasterApi.js` using Matrix bearer token, tenant key and refresh-token pattern.
- Added `src/services/partyMasterMapper.js` to isolate legacy React field names from the new API DTO.
- Customer list -> `GET /api/customers`
- Customer account groups -> `GET /api/customers/account-groups`
- Customer create -> `POST /api/customers`
- Supplier list -> `GET /api/suppliers`
- Supplier account groups -> `GET /api/suppliers/account-groups`
- Supplier detail/edit -> `GET /api/suppliers/{id}`
- Supplier create -> `POST /api/suppliers`
- Supplier update -> `PUT /api/suppliers/{id}`

## Account group behavior
- Default `isDefault=true` group is selected on Add.
- Selected account group's `accountNo` is sent as `glAccountNo`.
- Removed the old integration trick that copied selected GL into `clCode`/Customer ID.
- Supplier Group of Accounts select now binds to `clActNo`; visible UI/layout is unchanged.

## Deliberately unchanged
- CustomerForm visual layout/labels/order.
- SupplierForm visual layout/labels/order.
- CommonTable columns and Add button layout.
- Existing validation definitions, except Customer's obsolete `clCode` requirement is ignored because party ID is now generated by the API.
- Country continues to use the existing bootstrap `comboBox.country` to avoid UI churn.
- Delete icon behavior remains untouched/not wired because deletion UX was not implemented in the Old React baseline.
