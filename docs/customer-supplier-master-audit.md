# Customer / Supplier Master API

## Legacy mapping

- `dbo.rfParty` is the accounting party master.
- `Prt_Type='1'` = customer; `Prt_Type='2'` = supplier.
- `dbo.SP_Act_SaveParty` remains the authoritative create/update path.
- `dbo.SP_DELETE_Party` remains the authoritative safe-delete path and refuses deletion when `Act_Ledger` rows exist.
- `rfCustomerInfo` remains the retail/KYC customer table used by the sales lookup endpoint. `SP_Act_SaveParty` also maintains it when a Civil ID is supplied.
- `SP_Act_SaveParty_OldDatabase` and `App_LinkOldDatabase` are intentionally not used by this web module.

## API

Customer master:
- `GET /api/customers?term=&take=50`
- `GET /api/customers/{customerId}`
- `POST /api/customers`
- `PUT /api/customers/{customerId}`
- `DELETE /api/customers/{customerId}`

The existing `GET /api/customers/search?civilId=&mobileNo=` remains the retail/KYC sales lookup.

Supplier master:
- `GET /api/suppliers?term=&take=50`
- `GET /api/suppliers/{supplierId}`
- `POST /api/suppliers`
- `PUT /api/suppliers/{supplierId}`
- `DELETE /api/suppliers/{supplierId}`

Customer endpoints require the Sales module; supplier endpoints require Purchasing.

## Server-owned values

The API never accepts CompanyId, LocationId, financial year, user number or party type from the client. They come from authenticated context / active financial-year configuration. New party IDs are generated by `SP_Act_SaveParty` via its OUTPUT parameter. GL defaults follow the legacy master forms and are resolved from `Sys_Location` (`LocDebtorAct` for customers / `LocCreditorAct` for suppliers), currency defaults to `Sys_Company.BaseCurrencyId`, and account prefix/level are resolved from the selected GL group.

## Compatibility note

The supplied legacy `SP_Act_SaveParty` CREATE statement has `Prt_AreaId` and `Prt_ActFlag` values reversed relative to its INSERT column list. To avoid changing the shared legacy stored procedure, the API passes a blank area only for CREATE and corrects `Prt_AreaId`/`Prt_ActFlag` immediately afterward inside the same SQL transaction. UPDATE uses the stored procedure mapping directly because that branch maps the columns correctly.
